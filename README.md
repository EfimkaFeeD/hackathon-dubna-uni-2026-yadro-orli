## Инструкция по развертыванию Podcast Silence Remover

Данный документ содержит техническое руководство по подготовке окружения и запуску системы автоматического удаления тишины. Проект включает в себя Rust-бэкенд и C++ плагин для обработки сигналов.
Предварительные требования

Для корректной сборки и запуска всех компонентов системы необходимо предварительно установить следующее программное обеспечение:
### Установка Docker

  - Windows: Скачать [Docker Desktop](https://www.docker.com/products/docker-desktop/)
  - Linux: Устновка в зависимости от вашей OS.
    
### Установка Just

Подробную информацию об инструменте можно найти в официальном репозитории [just](https://github.com/casey/just).

### Процедура запуска

Управление жизненным циклом проекта осуществляется через команды утилиты just из корневой директории.
1. Инициализация проекта

Перед первым запуском необходимо подготовить структуру директорий и конфигурацию среды:
```Bash
just setup
```
Эта команда создаст необходимые рабочие папки и проверит наличие файла .env.
2. Запуск в режиме разработки

Для полной сборки всех компонентов и запуска системы в контейнерах:
```Bash
just dev
```
Команда выполнит сборку плагина, бэкенда и сервиса хранилища, запустит их в фоновом режиме и начнет трансляцию логов бэкенда в терминал.
### Описание команд `Just`

Ниже приведено описание основных сценариев, определенных в `justfile`:

  - `default`: Вывод списка всех доступных команд (список аргументов).
  - `setup`: Инициализация проекта: создание системных директорий и конфигурация окружения (.env).
  - `build-ffmpeg`: Изолированная компиляция C++ плагина внутри контейнера `plugin-compiler`. Результат сохраняется в директорию `./shared_plugins`.
  - `build-storage`: Принудительная пересборка и запуск сервиса хранилища (Storage Service) на порту 8081.
  - `run-storag`e: Запуск существующего контейнера сервиса хранилища.
  - `stop-storage`: Остановка работы сервиса хранилища.
  - `logs-storage`: Вывод журналов работы сервиса хранилища в реальном времени.
  - `dev`: Полный цикл развертывания: сборка всех образов, запуск всех сервисов проекта и вывод логов бэкенда.
  - `down`: Остановка и удаление всех активных Docker-контейнеров проекта.
  - `clean`: Полная очистка рабочего пространства, включая выполнение down и удаление временных файлов сборки.
